# 排错

> 顺序建议：**先看 `data\pet.log` 和 `data\pet-host.log` 最后 20 行**，再对照下面的症状表。
> 托盘右键 →「打开日志」可以直接打开。

## 1. 起不来

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| 双击 `.bat` 一闪而过，没窗口也没日志 | 目录在 **AI 代理的工作区**里，文件带 `S-1-4-*` / `Everyone:Deny` 权限 → Chromium 沙箱静默崩溃（`0x80000003`） | 把整个文件夹**复制到 `D:\` 之类普通目录**再跑。`check-runtime.ps1` 会打印这个警告 |
| 日志里 `第一次没起来, 改用 --no-sandbox 重试`，还是不行 | 沙箱 / 杀软拦截 | 手动 `BlueFishDeskpet.exe --no-sandbox` 看报错；或把目录加进杀软白名单 |
| 窗口在、`isVisible` 也 true，但屏幕上一个像素都没有 | 透明窗口靠 GPU 合成，驱动 / 远程桌面 / 虚拟机显卡出问题 | `$env:DSP_DISABLE_GPU='1'` 再启动（软件渲染），确认是不是 GPU 的锅 |
| 报 `缺少 BlueFishDeskpet.exe` | 还没装运行时 | 双击 `首次安装.bat`，或 `tools\setup-runtime.ps1` |
| 装运行时卡在 `downloading` | GitHub 慢 | 脚本会自动换 npmmirror；都不行就手动下 zip 用 `-Zip` 参数 |
| 图标 / 名字没盖上（还是 Electron 图标） | `patch-exe.ps1` 要下 1 MB 的 rcedit，网络失败 | 有网时重跑：`powershell -File tools\patch-exe.ps1`。**不影响运行** |
| 启动第二个实例没反应 | 单实例锁：第二次启动会把已有的叫到前面 | 正常行为。要重启就先从托盘退出 |

## 2. 没声音

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 她只冒气泡，不念 | **没装本地语音**（包不带） | 跑 `tools\setup-tts.ps1`（约 40 MB）；或者就这样，气泡照常 |
| 右键「声音」显示「这台机器没装语音文件」 | 同上 | 同上 |
| 装了还是不出声 | 声音总闸关着 / 系统音量 / 音效方案 | 右键「声音」三态切到「音效 + 念出来」；看 `pet.log` 里 `念:` 那行有没有 `合成 xxx ms` |
| `语音合成失败（之后不再出声）` | onnxruntime 崩溃 / 模型文件损坏 | 删 `resources\app\vendor\tts\` 重跑 `setup-tts.ps1`；日志里有具体错 |
| QQ 里她只打字，不发语音 | 没配火山 Key / 关了开关 | 右键「音色…」→ 填 Key → 保存；看状态是不是「已配置」 |
| QQ 语音发出去但对方收不到 | 多段 mp3 中间带 ID3 头（旧版 bug），NapCat 转码失败 | 本版已修；如果还遇到，看日志里是不是 `Failed to send audio packet` |
| 她在 QQ 里说话前先来一句"不确定能不能发" | 角色卡旧版措辞被内化 | 本版已改角色卡 + 不收这类自我观察；如果你自己改过 `companion-role.md`，检查有没有「不确定能不能」 |

## 3. QQ 连不上 / 她不回

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 小手机角标是 `!` | 要扫码登录 | 设置页「QQ 连接」看二维码；或 `NapCat\cache\qrcode.png` |
| 「启动 / 连接」后一直「等 OneBot 连上」 | NapCat 没起来 / 目录指错 / 端口被占 | 看 `data\napcat.log`；确认目录里有 `NapCatWinBootMain.exe`、`QQ.exe`、`napcat.mjs` |
| 二维码一直"等 NapCat 生成" | 旧版 bug：读登录态失败就 return，没人管码 | 本版已修；多等 10 秒或重开桌宠 |
| 点了「重新登录」没用 | 旧版凭据失效但返回 `200 Unauthorized`，缓存 50 分钟 | 本版已修；不行就重启桌宠 |
| 显示「已连接」但 QQ 里不回 | 挡位在 ①（保持连接不通讯）；或 `respond: false` | 点小手机切到 ② |
| 回两遍 / 双回 | 同一个 QQ 号被两条路同时接（内置 + 外部 kit） | 设置里「连接方式」只留一个 |
| 群聊里一声不吭 | 默认「群里只认 @」 | @ 她，或把群聊概率调高 |
| 她发不出图 / 手机回灌没来 | 设置页「主人 QQ 号」没填 | 填上你自己的 QQ 号（`ownerIds`） |
| QQ 掉线后自己回来了 | 网关看门狗：30 秒 → 1 → 2 → 4 → 5 分钟退避重启，最多 5 次 | 正常行为；超过 5 次点「启动 / 连接」 |

## 4. 手机连不上

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 第三挡一直「开机」 | MuMu 冷启动 30~60 秒 | 等；或切回第一挡再点第三次 |
| 日志「找不到 MuMu」 | 安装目录不在候选表 | 设置页 / `companion.json` 填 `phone.home`（指向含 `nx_main\` 的那层） |
| `adb connect` 失败 | 模拟器没开 / 端口变了 | `nx_main\MuMuManager.exe adb -v 0` 打印端口；填进 `phone.serial` |
| 她点空、或一直说"到底了" | 分辨率不是 720×1280 竖屏；或自绘界面 | 改分辨率；自绘界面按文字点无效（已知限制） |
| 中文输入失败 | `MuMuManager -c input_text` 是"成功不打印"的 | 看退出码；`pet.log` 里有每一步 |
| 她"光说不做" | 手机没开（第一挡），或者指令被守卫挡了 | 确认第三挡；把话说成短祈使句（「往下滑」「打开 B 站」） |
| 她做得太频繁 | 自主玩额度太宽 | `companion.json` 的 `phone.autonomy`：`enabled: false` 只在你叫她时动手机 |
| 她打开了别的 App | 图标名字太像 / 没验证到 | 本版会**验前台包名**；还不对就手改 `data\companion\phone\apps.json` 里的别名 |

## 5. 模型 / 记忆

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 报 401 / 403 / 404 / 400 | Key 无效、模型名不对、余额不足 | 立刻失败（不重试）；设置页「测试连接」/「测试 QQ 模型」会显示上游原话 |
| 报 503 / 429 / 网络错误 | 上游繁忙 | 自动重试 4 次（0.7s / 1.8s / 4s）；QQ 那边还会 15s / 45s 补发，都不行她会说「我这边暂时连不上」 |
| 她答得牛头不对马嘴 | 上下文被截断 / 模型太小 | 看设置页「模型遥测」里是不是 `finish_reason=length`；把 `maxTokens` 调大或换模型 |
| 长期记忆很脏 | 早期迁移进来的流水账 | 设置页「长期记忆」面板搜索 / 删除；或跑 `node tools\memory-prune.cjs`（默认 dry-run，先备份） |
| 她把你的性子记成了自己的 | 归属判定出错 | 看「她的账」窗口；人物账在 `data\companion\people.json`，近义重复可用 `tools\memory-compact.cjs` |
| `data\userdata\` 越来越大 | Chromium 的缓存 | 退出桌宠后删掉，下次自动重建（登录态在 `config\`，不在 `userdata\`） |

## 6. 自检

```powershell
node test\smoke.cjs               # 全量 2136 项 / 约 1.5 分钟
node test\smoke.cjs --list        # 58 个区域
node test\smoke.cjs 手机           # 只跑名字或标签带"手机"的
node test\run-one.cjs 33-phone-open.cjs
$env:DSP_SMOKE_TIME=1; node test\smoke.cjs    # 打每个区域耗时
$env:DSP_SMOKE_TRACE=1; node test\smoke.cjs   # 红的时候给 stack
```

- 自检**不需要 Electron**，纯 Node；它自己在临时目录里造配置、放假端点，**不会碰你的 `data\`**。
- `--list` 打出来的每个区域都可以单跑；`05*` 那 7 个区域共用一条连接，要按文件名顺序跑。
- 装本地语音之后某些区域会多几项（要真加载 sherpa），属正常。

## 7. 还是不行

收集这三样东西，基本能定位：

1. `data\pet.log` + `data\pet-host.log` 最后 100 行；
2. `powershell -File tools\check-runtime.ps1` 的完整输出；
3. 你做了什么（哪个挡位、点了什么、说了什么）。
